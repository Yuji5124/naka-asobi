# ひなあそび

4〜7歳向けの、文字・形・迷路・発見と景品集めを指で楽しむWebアプリ。HTML / CSS / JavaScriptだけで動き、ビルド・ログイン・外部API・有料サービスは不要です。教材タブレットの「触る → 試す → 即反応 → もう一度」という短いループを、オリジナルのUI・SVGイラスト・白い友達キャラクターで実装しています。

## タブレット向けの画面

横向きタブレット（1024×768〜1180×820）を基準にした画面です。ホームは青空・草原・家・池のオリジナルSVG風景、遊びの選択は6枚の絵カードを2段に配置。公園・ごほうび・たからものは2ページ目にまとめ、カテゴリ内でステージを選びます。遊びの画面は左〜中央に操作エリア、右に友達キャラクターと吹き出し、下にやり直し・次へボタンを置き、スクロールなしで操作できます。描画エリアは標準タブレットで400 CSS px以上、描線はクレヨン風です。縦向きタブレット・スマホでは縦配置に切り替わります。

タイトルの中央の「あ」は `home-art.js` のSVG線画です。iPadの日本語フォントやボタンの標準余白に依存せず中央に収めます。タイトル名は5文字を同じ幅の枠に並べ、雲の枠・旗・あひる・積み木・ちょうちょを添えています。ホーム専用の調整は `home.css` にまとめています。

風景とカードは解像度に依存しないSVGで作成しています。外部画像やフォントの読み込みはありません。

## 起動

```sh
cd /workspace/naka-asobi
python3 -m http.server 8000 --bind 0.0.0.0
```

ブラウザでポート8000を開きます。一般的な静的Webサーバーでも動作します。

## 遊び

ホーム → あそびをえらぶ → みつける → なぞる → つなぐ → かく → 結果 → ホーム。
選択画面からどの遊びにも入れます。対象は「あ・し・つ・く・へ・ほ・の」の7文字です。

- **みつける**：8枚のカードから「あ」を3個探します。間違いにも揺れと音で反応します。
- **なぞる**：「し・つ・く・へ」を選択。①から順に軌道の近くを通ると成功。書き始め・進行順・軌道の通過率で判定し、ただの落書きではクリアしません。
- **つなぐ**：横・曲がり・縦の道をドラッグして、文字を絵まで届けます。パーツをタップ → 空きマスをタップでも操作できます。T字を含む違うパーツは優しく再試行を促します。「ちがう もじ」で6種類の絵を選べます。
- **すうじを つなぐ**：「つなぐ」→「すうじをつなぐ」→レベル選択。各レベル3ステージです。レベル1は1〜3のペア、レベル2は2〜4組の散らばった数字、レベル3は4〜6組（1〜6）を探します。数字から同じ数字まで指やペンを離さず線を引き、描線は途中・正解後も残ります。「つぎへ」で進み、3ステージ完了で1ポイント。
- **いろぬり**：「もっと あそぶ」→「いろぬり」→レベル選択。レベル1は形をタッチして1・2・3色で塗ります。レベル2は大きな丸・四角・三角をペンや指で塗ります。描いた部分だけに色がつき、図形の外にはみ出さず、内部をおおむね65%塗ると成功です。各レベル3ステージ完了で1ポイント。旧レベル1の進行を保ち、追加レベルの進行とログは別に保存します。
- **かく**：「ほ」を自由に書きます。3本以上の線・描画量・幅と高さ・領域・大まかな開始位置でゆるく判定。成功すると書いた線に目がつき、動きます。文字認識ではないため、形の正確さは判定しません。
- **ずかん**：遊んだ文字の読み・関連する絵・順に動く簡易書き順ガイドを表示します。ガイドは本格的な書写教材の代替ではありません。

Pointer Events対応。タッチ／マウスで同じ操作ができます。パズルはタップ方式も使えます。音はWeb Audio APIのオリジナルの静かなオルゴール風BGMと短い効果音です。最初の操作で開始し、おとのボタンで両方を切り替えます。非表示時は音を止めます。SpeechSynthesisによる読み上げは削除しました。文字・絵・書き順の動きと音で反応を返します。

## かたちの遊び

「はじめる」→「かたち」から、写真の学習構造をもとにしたオリジナルの3種類の遊びを選べます。

- **まわす**：見本と同じ積み木を、矢印または横ドラッグで90度ずつ回転。見本と同じ向きになると成功します。回転中も見え方が変わります。
- **つむ**：黄色・青・緑の積み木を台にドラッグ、または色を選択して台／積み木をタップして重ねます。「ひとつもどす」で外せます。見本と同じ配置・色の組み合わせで成功。台の上で位置がずれていても同じ構造なら成功します。浮いた積み木は作れず、1列3段・全体12個まで置けます。台を横ドラッグ、または矢印で回すと見本も同じ方向に回り、隠れている部分を確認できます。
- **ならべる**：三角・四角・丸をシルエットへドラッグ、または形→置き場所をタップ。三角は大きな「ひだりにまわす」「みぎにまわす」で回せます。ロケット・家・車・船の4種類。違う形／向きなら優しく再試行を促します。

立体は `shapes.js` 内の座標と回転角からSVGの面を投影する独自の軽量レンダラーです。WebGLや3Dライブラリは不要。見本の向き合わせ・構造合わせを行う遊びで、物理シミュレーションや画像認識ではありません。各遊びには4問あり、次の問題／やり直し／ホーム移動ができます。

## 迷路の遊び

「はじめる」→「めいろ」から、どんぐり・ちょうちょ・ロケットの形をしたオリジナル迷路を選べます。あおい丸から指またはマウスで道をたどり、黄色いゴールを目指します。枝分かれや行き止まりがあり、引き返せます。壁に当たるとその手前で止まり、別の道を試すよう案内します。素早いドラッグも経路を細かく検査するため、壁を飛び越えてクリアできません。

指を離したらあおい丸から続けられます。「もういちど」で線を消し、クリア後は「つぎのめいろ」で切り替えます。迷路にフォーカスして矢印キーでも操作できます。`maze.js` が迷路の分岐・当たり判定・SVG描画を担当し、外部ライブラリは使いません。完成した迷路の種類を記録に残します。

## 保存

`localStorage` の `hiragana-asobi-v1` に、遊んだ文字・クリアした遊び・最近遊んだ文字・スタンプ・音設定・遊んだかたちの種類・完成した迷路の種類と、下記の報酬・ローカルログを保存します。旧版の文字の記録を引き継ぎます。個人情報は保存しません。保存が禁止されたブラウザでも遊べますが、記録は次回に残りません。

## GitHub Pages

リポジトリの **Settings → Pages → Deploy from a branch** で `main` の `/ (root)` を選択してください。`index.html`、`style.css`、`shapes.css`、`app.js`、`shapes.js`、`maze.js`、`maze.css`、`experiment.js`、`experiment.css`、`extras.js`、`celebrations.js`、`sound.js`、`home-art.js`、`home.css`、`favicon.svg`、`assets/` が配信されます。すべての参照を相対パスにしているため、`/naka-asobi/` 以下でも動作します。ビルドやルーターのフォールバック設定は不要です。GitHubへの反映後、Pagesの配信完了はGitHubのActions / Pages画面で確認してください。

## ブラウザ検証

起動した状態で、PlaywrightとChromiumが利用できる環境なら以下を実行できます。

```sh
node tests/playtest.cjs
node tests/shapes-playtest.cjs
node tests/maze-playtest.cjs
node tests/experiment-playtest.cjs
node tests/experiment-layout.cjs
node tests/path-orientation-playtest.cjs
```

テスト用Playwrightはアプリの実行には不要です。`CHROMIUM_PATH`（既定 `/usr/bin/chromium`）、`TEST_BASE_URL`（既定 `http://127.0.0.1:8000`）、`TEST_ARTIFACT_DIR`（既定 `/tmp/hiragana-playtest`）でテスト環境を切り替えられます。

横向きタブレットを初期画面にして操作を検証する場合：

```sh
TEST_VIEWPORT='{"width":1024,"height":768}' node tests/playtest.cjs
```

テストはタブレット横画面のスクロール不要・描画領域の大きさも確認します。実機のSafari/iPadOSやAndroid固有の挙動は、公開URLを端末で開いて確認してください。

`shapes-playtest.cjs` は回転・積み木のドラッグ／タップと取り消し・形合わせの向き・記録の互換性・タブレット／スマホ表示を検証します。

`maze-playtest.cjs` は実際のタッチ入力で2種類のクリア・壁での停止・途中再開・やり直し・キーボード・既存記録との互換性・6種類の画面サイズを検証します。

## 追加ステージと報酬

- みつける1：従来の文字探し。みつける2：公園のコイン探し。木・ベンチ・滑り台・ブランコ・砂場・花・石・看板などのオリジナルSVG風景に5つのコインを置きます。毎回12候補から抽選し、直前と同じ5候補は避けます。5つ全部を見つけて1ポイントです。探すコインと、クレーンに使える所持コインを直接交換しません。
- なぞる2：「の」を新しく追加。まるい軌道をたどります。
- つなぐ2：左端を下へ進んでから、右へつなぐ別ルートです。
- かく2：山のような「へ」を1本で書き、動く文字にします。
- かたち2：新しい積み木の橋と船の形合わせから開始します。
- めいろ3：ロケットの枝分かれした迷路です。

各クリアで1ポイント。ポイントは累計で消費しません。**累計5ポイントごとにコイン1枚**です。5ptで1枚、10ptで2枚、15ptで3枚。上部の星は次のコインまでの進捗（0〜4 / 5）、コインは現在使える残高です。5pt到達でクレーンが解放され、所持コインが1枚以上あると遊べます。実際に「あそぶ」を押した時だけ1枚消費します。途中でホームへ戻っても、開始済みの1回の消費は戻りません。クレーン自身からポイントは得られません。

左右のスライダー→「とる！」の2操作。景品の中心近くへ合わせると成功し、外すと失敗します。うさぎ・バス・プリン・不思議な星はすべてオリジナルSVG。重複もたからものに保存します。

通常クリアは、はなまる／花火をランダムに約2.1秒表示します。その後、5pt到達時はコイン回転→上部へ移動（約1.4秒）を追加します。保存はクリア時点で確定し、画面を切り替えても報酬は失われません。演出は入力を妨げず、次の操作で片付きます。OSの動きを減らす設定では短縮します。

## 保護者ログとデータ構造

ホームの小さな「きろく」から子ども向けゲームと別の画面へ入ります。プレイ回数・総時間・ゲーム別回数／時間／平均時間／クリア率、最近のセッション、ポイント・コイン収支・クレーン回数・景品数、演出別の表示／もう一度を確認できます。従来のなかよし記録もここから開けます。JSONの保存で後から分析・比較できます。出力には `gameSummary` としてゲーム単位の平均時間・クリア率も含みます。外部サーバーへは送信しません。

`experiment.js` が旧保存キー `hiragana-asobi-v1` の中に `schemaVersion: 2` の領域を追加します。旧文字・形・迷路・音の記録を引き継ぎます。記録がなかった時期のプレイ数や時間を推定して追加しません。

- `totalPoints`, `coinBalance`, `totalCoinsEarned`, `totalCoinsSpent`：累計ポイントと独立した収支。復元時も獲得コインは `floor(totalPoints / 5)`、残高は獲得−使用の関係を保ちます。
- `collection[]`：景品ID、取得日時、元のセッションID。
- `playLogs`：`gameId:stageId` ごとの `gameId`, `stageId`, `playCount`, `totalPlayTime`（秒）, `lastPlayedAt`, `completedCount`。
- `sessions[]`：ID、ゲーム／ステージID、`appVersion`、開始・終了・チェックポイント日時、`durationSec`, `completed`, `endReason`, 演出、演出直後の再試行。`completed` は各セッションで1度だけ立ち、取り消し→再完成でポイントを二重加算しません。
- `coinTransactions[]`：獲得／使用、枚数、ゲームの発生元、日時、セッションID。
- `effects`：はなまる／花火ごとの `shown`, `retries`。そのセッションでクリア後に「もういちど」を押すと再試行を記録します。ホーム経由の入り直しや「つぎへ」はこの数に含めません。

ゲームIDは `find`, `trace`, `path`, `write`, `shape`, `maze`, `find2`, `crane`。同じ遊びでもステージIDを分け、公園を従来のみつけると比較できます。`gameStats()` は集計値から `averagePlayTime = totalPlayTime / playCount` と `completionRate = completedCount / playCount` を算出します。セッションから短時間離脱・反復・バージョン更新前後を分析できます。

時間は表示中だけ加算し、非表示・移動・`pagehide` でチェックポイントを保存します。5秒ごとにも保存するため、OSによる強制終了では最大約5秒の直近操作が残らない場合があります。復元時に終了していないセッションは保存済みの時刻で区切り、閉じていた時間は加算しません。ブラウザが保存を許可しない場合もメモリ上で遊べます。ログは自動削除しないため、長期間の利用ではJSONを保存して観察してください。

`experiment-playtest.cjs` はスマホとタブレットの実タッチ入力で追加ステージ全種、演出2種類、5/10/15ptの換算、二重獲得防止、クレーン成功／失敗／中断、使用履歴、旧保存互換、時間ログ、リロード、JSON保存を確認します。`experiment-layout.cjs` は320/768/960/1024/1180pxでカテゴリ整理・ステージ選択・公園・クレーン・56px以上の回転UIを確認します。

追加レベルの動作確認：`TEST_BASE_URL=http://127.0.0.1:8133 node tests/link-color-levels-playtest.cjs`。数字全9ステージ、色ぬり、線の保持、図形外のクリッピング、進行・報酬・ログの保存と復元をスマホと縦横タブレットで確認します。
